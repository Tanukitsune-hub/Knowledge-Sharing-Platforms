# 部内共有ナレッジ基盤：MVPと開発ロードマップ

作成日: 2026-08-02

ステータス: 構想・要件整理

## 1. 開発方針

本プロジェクトは、機能を一括実装せず、利用者負担と利用価値を小規模パイロットで検証しながら段階的に拡張します。

優先順位は次のとおりです。

1. 共有ドライブ上に記録と資料が安定して残る
2. 面談先・人物・日付から過去記録を探せる
3. 新規・既存Docsを短時間で登録できる
4. 面談準備に役立つ要約・論点を表示できる
5. 利用実績を確認してから高度なAI検索を追加する

## 2. Phase 0：前提確認と設計確定

実装開始前に、次の事項を確認します。

### 2.1 Google Workspace

- 共有ドライブを作成できるか
- 共有ドライブを2つに分けられるか
- AppSheet Coreまたは必要な上位ライセンスを利用できるか
- AppSheetが管理者により許可されているか
- Apps Script Web Appの利用が許可されているか
- 部門管理用Workspaceアカウントを作成できるか
- Googleグループで権限管理できるか

### 2.2 AI利用

- Gemini APIまたはVertex AIを業務利用できるか
- 面談記録をAI処理できる情報区分は何か
- 無料枠ではなく会社承認済みの有料・管理環境を使えるか
- 利用リージョン、ログ保持、データ利用条件に問題がないか
- APIキーまたは認証方式を安全に管理できるか

### 2.3 データ・運用

- 既存Excelの項目とデータ量
- 既存Docs・資料の保存場所
- 面談記録の情報区分
- 削除・保存期間のルール
- 想定利用者数
- 初期パイロット利用者
- 運用管理者とシステム管理者

### 2.4 Phase 0の成果物

- UI方式の決定: AppSheetまたはApps Script Web App
- AI接続方式の決定
- 共有ドライブ構成
- 権限設計
- MVP要件確定
- 匿名化テストデータ
- パイロット計画

## 3. Phase 1：UIプロトタイプ

実データ・AIを使わず、操作性のみを検証します。

### 3.1 対象画面

- ホーム
- 検索
- 新規面談登録
- 既存Docs登録
- 面談詳細
- 面談先詳細
- 人物詳細
- 自分の確認事項

### 3.2 検証項目

- 初見で操作方法が分かるか
- 面談登録が1分以内に完了するか
- 既存Docs登録が30秒以内に完了するか
- 過去面談を3操作以内で開けるか
- 一覧に必要な情報が過不足なく表示されるか
- スマートフォン・PC双方で利用可能か
- Spreadsheetを意識せず使えるか

### 3.3 プロトタイプ合格条件

- パイロット利用者が説明なしでも主要操作を完了できる
- 必須入力項目が原則2項目に収まる
- 画面遷移や用語について重大な迷いがない
- システム管理項目が一般利用者に露出しない

## 4. Phase 2：MVP

### 4.1 MVPに含める機能

| 機能 | MVP |
|---|---:|
| 共有ドライブへの正本保管 | 対象 |
| 利用者向けApp UI | 対象 |
| 新規面談登録 | 対象 |
| 面談Docsの自動作成 | 対象 |
| 面談資料フォルダの自動作成 | 対象 |
| 既存DocsのURL登録 | 対象 |
| ファイル存在・アクセス確認 | 対象 |
| 面談一覧・検索 | 対象 |
| 面談先別履歴 | 対象 |
| 人物別面談履歴・回数 | 対象 |
| 元Docs・資料フォルダへのリンク | 対象 |
| AI要約・主要論点抽出 | 条件付き対象 |
| 未確認事項・TODO候補抽出 | 条件付き対象 |
| 簡易確認画面 | 条件付き対象 |
| 面談前ブリーフ | 次段階 |
| Calendar連携 | 次段階 |
| Gmail連携 | 対象外 |
| 高度なRAG | 対象外 |

AI機能は、社内承認と情報管理上の条件を満たした場合のみMVPへ含めます。承認が間に合わない場合でも、検索・リンク・履歴管理を先行稼働させます。

### 4.2 MVPの利用フロー

#### 新規面談

1. 利用者が「新しい面談記録を作る」を選択
2. 面談日と面談先を入力
3. 共有ドライブ内に面談Docsと資料フォルダを自動作成
4. 利用者がDocsへ自由に記録
5. 必要に応じてAI処理を実行
6. 検索・面談先履歴に反映

#### 既存Docs

1. 利用者が「既存Docsを登録する」を選択
2. Docs URLを貼り付ける
3. システムがアクセス権と保存場所を確認
4. 共有ドライブへ移動・コピー、または外部参照として登録
5. 検索・履歴に反映

### 4.3 MVP受入条件

- 一般利用者がSheetsを直接操作せずに利用できる
- 新規面談登録が1分以内に完了する
- 既存Docs登録が30秒以内に完了する
- 面談先、人物、日付で検索できる
- 各検索結果から元Docsと資料へ移動できる
- 個人アカウントに依存する本番資産がない
- ファイル削除・権限不足・AI処理失敗がログに残る
- AI出力には原資料参照が付く
- AIを停止しても基礎機能が利用できる

## 5. Phase 3：既存データ移行

### 5.1 移行方針

過去データを最初から完全に正規化しません。利用価値の高いデータから段階的に移行します。

優先順位:

1. 現在デューデリジェンス中の面談先
2. 重要な既存投資先・運用会社
3. 直近2年の面談記録
4. 継続確認事項がある面談
5. その他の過去記録

### 5.2 既存Excelから移行する初期項目

- 面談日
- 面談先
- 面談相手
- 関連ファンド・戦略
- 記録作成者
- 既存記録の保存場所
- 備考

### 5.3 移行方法

| データ状態 | 方法 |
|---|---|
| Excel内に記録本文がある | 面談単位でDocs化し、索引を作成 |
| 既存Docsがある | URL登録し、共有ドライブへ移動またはコピー |
| 資料のみ存在する | 面談または組織に関連付けてFilesへ登録 |
| 所有者不明・アクセス不可 | 移行保留一覧へ記録 |
| 重複する記録 | 原資料を保持したまま統合候補へ回す |

## 6. Phase 4：業務統合

MVPの利用定着と品質を確認後、次の機能を優先順位順に追加します。

### 優先度A

- 面談前ブリーフ生成
- 未確認事項の継続表示
- 面談先別の主要論点推移
- 人物の所属・役職履歴
- 既存タスク管理システムへの確定TODO連携

### 優先度B

- Google Calendarから面談予定を選択
- 面談日、参加者、タイトルの自動入力
- 過去面談との差分抽出
- ファンド別・戦略別ビュー
- ナレッジ品質管理画面

### 優先度C

- AIによる自然言語質問検索
- 意味検索・RAG
- 参照資料を含む横断的な面談準備
- 部内レポート・定例資料の生成補助

## 7. パイロット計画

### 7.1 対象

- 3〜5名程度
- 面談頻度が高い担当者を含める
- 記録の書き方が異なる利用者を含める
- 管理者以外の一般利用者を必ず含める

### 7.2 期間

4〜6週間を目安とし、実際の面談で利用します。

### 7.3 評価項目

- 登録件数
- 検索回数
- 面談前に過去記録を参照した回数
- 入力・登録時間
- 登録途中の離脱
- 検索結果から原資料を開いた割合
- AI要約・抽出の修正率
- 利用者が感じた時間削減
- 継続利用意向

### 7.4 導入判断

次の条件を満たす場合に部内展開します。

- 利用者が登録負担より検索・準備の便益を大きいと評価する
- 主要操作で継続的な迷いがない
- 原資料リンク切れが許容水準に収まる
- AI抽出の重大な誤りを人が検知できる
- 運用管理者が無理なく保守できる
- 情報管理・権限上の重大課題がない

## 8. テスト方針

### 8.1 機能テスト

- 新規面談作成
- 既存Docs登録
- 共有ドライブ判定
- ファイル移動・コピー
- 検索
- 組織・人物の紐付け
- AI処理
- 再処理
- ログ出力

### 8.2 権限テスト

- 一般利用者
- ナレッジ管理者
- システム管理者
- 退職・無効化された利用者
- 外部所有ファイル
- アクセス権を失ったファイル

### 8.3 品質テスト

- 異なるDocs書式
- 長文記録
- 箇条書き中心の記録
- 文字起こし
- 日本語と英語が混在する記録
- 同姓同名
- 組織名・ファンド名の表記揺れ
- AI出力の事実・所感混同

### 8.4 継続性テスト

- 個人アカウントを無効化しても動作するか
- トリガー所有者変更後も動作するか
- 管理者交代手順が再現できるか
- バックアップから索引を復元できるか

## 9. リリース管理

推奨環境:

- Development
- Test
- Production

最低限、テスト用の匿名化データと本番データを分離します。

GitHubでは、設計書とソースコードをPull Requestでレビューし、リリースごとにタグを付与します。Apps ScriptやAppSheetの本番変更についても、変更内容、実施者、実施日、ロールバック方法を記録します。

## 11. 完了の定義

本プロジェクトの初期完成は、単に機能が動くことではなく、次の状態を指します。

- 部内利用者が追加説明なしで登録・検索できる
- 記録を残す負担が既存運用より増えていない
- 過去面談を探す時間が明確に短縮されている
- 面談記録と資料が共有ドライブ上で継続的に管理される
- 管理者交代時にも運用を引き継げる
- AIを利用する場合、原資料と処理履歴を追跡できる
